# Comprehensive Architectural & Security Review: Python Remaster vs Original JS

This document is a file-by-file technical breakdown of the `fgc-remaster` (Python) project compared to the original `free-games-claimer` (Node.js).

If you are inspecting this codebase for security reasons, migrating your deployment, or simply wanting to understand how the internal logic was rewritten to cope with modern bot protections, this document lists every addition, modification, and omission.

---

## 1. Executive Summary & Security Posture

The original project relied on **Node.js** and **Playwright/Patchright**. While effective initially, advanced bot-protection services like Cloudflare Turnstile, hCaptcha, and Epic's in-house security have become exceptionally good at fingerprinting Playwright's Chrome DevTools Protocol (CDP) signatures.

The **Python Remaster** was built from the ground up to solve two critical flaws:
1. **Automation Detection**: The core was migrated to **Python 3** using [`nodriver`](https://github.com/ultrafunkamsterdam/nodriver), a CDP-based asyncio library that drives the official Chrome binary without the usual automation fingerprints.
2. **Data Corruption**: Volatile, highly concurrent `.json` file-writes were replaced with an ACID-compliant asynchronous **SQLite** database via `SQLAlchemy`.

On fingerprints the project deliberately does **less** than it used to. A hand-written desktop spoof (fake `Win32` platform, fake NVIDIA WebGL renderer, fake plugin list) shipped in an early release and started summoning captchas across every store, because those values did not match the real Linux container running it. That script was switched off in `1.4` and deleted in `1.13`, so stores run on the fingerprint nodriver's patched Chrome produces by itself. Exactly one module overrides it: AliExpress injects one coherent Android device (user-agent, client hints, screen, navigator, WebGL) generated by `browserforge`, because its check-in only exists on the mobile site. That phone names the version of the Chrome actually running, so it never claims an older Chrome than the engine underneath. Prime Gaming also hides passkey support (`PublicKeyCredential`, `navigator.credentials`) on its pages so Amazon offers the password form, removing the passkey forms only on Amazon's sign-in pages.

**There are no obfuscated binaries, no hidden tracking telemetry, and no unauthorized outbound requests.** Every request either fetches a target store (Epic, Fab, Steam, GOG, Amazon, Ubisoft, Unity Asset Store, Microsoft Store and Xbox, Microsoft Rewards (`rewards.bing.com`, `bing.com` and the pages its cards link to), AliExpress, Legacy Games, GamerPower and the page each of its giveaway links ends at, fetched once every two weeks without signing in to see which store it belongs to; the Itch.io, Fanatical, IndieGala and Alienware Arena sites), asks `api.github.com` for the latest release number so the bot can tell you your image is outdated (`NOTIFY_UPDATES=false` stops even that), asks `ipapi.co` (or `ipwho.is` when that fails) on the first run, and then once a month by default (`BROWSER_TIMEZONE_REFRESH`), which time zone your IP address is in, so the browser does not show UTC next to your IP (naming your zone, e.g. `BROWSER_TIMEZONE=Europe/Warsaw`, skips the lookup and keeps the zone; `TZ` does too; `BROWSER_TIMEZONE=off` skips it and leaves UTC), or dispatches a JSON payload to exactly the Discord/Apprise webhook you configured.

## 2. What was DROPPED? (File Omissions)

The following scripts from the original `free-games-claimer-dev` were deemed out-of-scope for a core gaming claimer or misleading, and were **deleted**:

- 🔄 `aliexpress.js`: Removed as a coin scraper, then reimagined and re-added as `aliexpress.py` per user request. It performs the daily check-in on the mobile coin page. AliExpress often serves that page empty, so the module walks back to it up to `AE_PAGE_RETRIES` times and then reports it instead of retrying for half an hour, see [issue #33](https://github.com/P-Adamiec/Free-Games-Claimer-Remaster/issues/33).
- 🔄 `unrealengine.js`: Removed at the time, and since replaced by something better. The Unreal Engine marketplace became **Fab**, and `src/stores/epic_fab.py` now claims its weekly limited-time free assets; `src/stores/unity.py` does the same for the Unity Asset Store. Both are asset stores rather than game stores, so both run only when `STORES` names them and both stay strict about what they accept: only an offer the storefront itself flags as free is ever claimed.
- ❌ `steam-games.js` (Original): The original JS project contained a file named `steam-games.js`, **but it never claimed games.** It only scraped your public Steam profile to read playtime hours and achievements. It was deleted and completely replaced with a real auto-claimer.
- ❌ `package.json` / `package-lock.json` / `eslint.config.js`: Entire Node.js ecosystem files removed in favor of Python's `requirements.txt`.
- ❌ `src/migrate.js`, `src/util.js`, `src/version.js` (now `src/version.py`), the five manual scripts in `test/*.js`, `jsconfig.json` and `sonar-project.properties`: Node.js tooling with no use in the Python project.
- ❌ The settings `RECORD`, `NOWAIT`, `TIMEOUT` and `LOGIN_TIMEOUT` (the wait for you is `VNC_LOGIN_TIMEOUT` now). The old `epic-games.json` / `gog.json` claim history is not imported: the new database starts empty.

## 3. What was ADDED & REWRITTEN? (File Additions)

### A. The Core Engine (`src/core/`)
Instead of duplicating browser launch logic in every single store file (as the JS version did), the Remaster uses a strictly Object-Oriented approach.
- 🟢 `claimer.py`: Contains the `BaseClaimer` class every store inherits from. It standardizes the `nodriver` launch flags (including `--restore-last-session`), maps each store to its own persistent profile under `data/browser/`, and lets one store ride another's session where that saves a login (Fab signs in as Epic, Microsoft Rewards as the Microsoft Store when it is the same account). Clicks and typing go through `_click_like_a_hand()` and `_type_like_a_hand()`: a real mouse path and real key events, and a letter with no key of its own is inserted the way an input method does. Screenshots follow `DEBUG`, are JPEG and are kept 90 days; `DEBUG_SCREENSHOTS` sends the failure ones. Teardown first asks Chrome to close, so cookies reach the disk, then kills the whole process tree with `psutil`, because stopping only the parent left orphans behind that broke the next run. It also owns the shared human hand-over: challenge detection, the "open noVNC and finish this" notification, and the wait that follows.
- 🟢 `database.py`: A new `SQLAlchemy` async ORM layout managing an `fgc.db` SQLite database. Every claim is keyed on a `(store, user, game_id)` tuple, so a game already recorded is never claimed twice, whatever the display title happens to be that week.
- 🟢 `config.py`: Replaces the old `config.js`. It strictly parses your `.env` file into a typed Python `Config` class. Store modules never read the environment directly, which is why every setting is documented in one table.
- 🟢 `notifier.py`: Sends each message to your Discord webhook (`httpx`) and to any Apprise service at the same time, split into parts each service accepts. Which events are sent is decided where each message is made, by `NOTIFY_SUMMARY`, `NOTIFY_ERRORS`, `NOTIFY_CLAIM_FAILS` and `NOTIFY_SKIP_STORES`, so the bot does not spam your server.
- 🟢 `redact.py` (**New**): Masks every password, two-factor secret, sign-in name, e-mail address, notification token and game code before a log line is printed, whichever library wrote it, because logs end up pasted into public bug reports. The name a store shows once you are signed in, your first name on Amazon for example, is masked from that moment on. Codes keep their first five characters so you can still tell them apart, and a public `VNC_URL` or `VNC_IP` shows as `***`; notifications keep everything in full.
- 🟢 `url_security.py`: One hostname check used by every redirect in the project. A giveaway link is trusted only when the resolved host really is the store, so a lookalike such as `gog.com.evil.tld` can never pass as GOG. Substring matching on URLs is banned in this codebase precisely because it accepted exactly that.
- 🟢 `selection.py`: Publishes which stores the current run covers, so a giveaway found by GamerPower is only claimed when this run includes the store it belongs to. `STORES=steam` claims the Steam giveaways it finds and leaves the Epic ones alone.
- 🟢 `run_state.py`: Remembers what one run learned about the person at the keyboard. A store whose VNC prompt went unanswered is not asked again in the same run, because waiting another full timeout changes nothing and re-opening its sign-in page over and over is what lowers a session's standing. It also keeps the checkout puzzles nobody solved for a meeting with you in noVNC, until shortly before the next run.
- 🟢 `display.py`: Watches the virtual screen (TurboVNC) the browser draws on. A dead screen used to fail every store with "Failed to connect to browser" and blank the noVNC page, so the bot now checks it before opening a window and starts it again through `start-vnc.sh`, or says once why it cannot. It also reads `/proc/net/tcp` to see when someone opens noVNC, so a kept puzzle's checkout opens again only then.
- 🟢 `browser_timezone.py` (**New**): Gives the browser the time zone your IP address is in, because a site that sees UTC next to a Polish IP sees a mismatch. It asks `ipapi.co` (or `ipwho.is`) on the first run and keeps the answer in `data/browser_timezone.json` for a month, or a week or a single run (`BROWSER_TIMEZONE_REFRESH`); `TZ` or `BROWSER_TIMEZONE` picks a zone yourself and `BROWSER_TIMEZONE=off` keeps UTC. Only Chrome gets the zone, the bot's own clock and log stay as they were.
- 🟢 `human_checks.py` (**New**): Notes every human check the bot meets (Cloudflare, a captcha, a sign-in captcha handed to you, AliExpress's slider, Bing's check) in `data/human_checks.json` for two weeks. The log ends each run with the count per store for the last seven days.
- 🟢 `src/version.py`: The one line that holds the release number, replacing the original's `src/version.js`.
- 🟢 `updates.py`: Asks GitHub once a day whether a newer release exists and notifies you once per version, with the release notes link. It sends nothing about you, and a failed request never blocks a run.

### B. The Store Modules (`src/stores/`)
- 🟢 `main.py`: The entry point. It runs the schedule (`SCHEDULER_HOURS`, `SCHEDULER_FIXED_TIMES`, `RUN_ON_STARTUP`, `RUN_ONCE`), takes the stores from the command line or `STORES`, asks GamerPower once and hands each find to its store, and sends one summary. `within_limit()` stops a store that runs past an hour plus four `VNC_LOGIN_TIMEOUT` waits, `keep_appointments()` opens a kept Epic or Fab checkout again once you connect to noVNC, and `warn_open_novnc()` tells you at start when noVNC has no password at a public address.
- 🟢 `epic.py`: Rewritten to force strict `headful` mode using `nodriver`: a visible browser with the GPU on (`force_headful`) draws fewer hCaptcha checks than a headless one, which is what halted the Node.js version. A picture puzzle in the checkout waits for you to open noVNC (`EG_CAPTCHA_ASK`): a puzzle you were asked about and did not solve in time is kept, and the bot opens that checkout again with a fresh puzzle once you connect, or tries once more by itself when the giveaway ends first. The checkout is pressed with real, checked mouse clicks instead of script clicks a page can tell apart, and an order is placed only when the checkout total reads zero, so a page that sells the game is never bought. A game on the free games list is opened by clicking its tile, the way a person gets there, and the page of a game you already own is read again only every three days; a Cloudflare check in front of a game page is waited out, and handed to you over VNC only for a game you do not have yet.
- 🟢 `epic_mobile.py`: Epic's weekly free Android/iOS game never appears in the promotions API the bot polls. Ported from the original's `src/epic-games-mobile.js`, this module reads the same listing, but from inside an Epic store page because Cloudflare refuses plain requests, and hands the URLs to the normal Epic claimer, which claims them on the same product pages. Detection only: no extra login, no extra browser, and a network failure returns an empty list rather than breaking the Epic run.
- 🟢 `epic_fab.py` (**New**): Claims Fab's limited-time free assets. Listings keep their original price and Fab's search API silently ignores unknown filters, so only the storefront's own `isLimitedFreeContent` flag authorises a claim, and ownership is read from the library API rather than from page text. Epic's checkout frame also sells assets, so an order goes through only when its total, or in Epic's newer checkout every price it shows, reads zero. Signs in on Epic's profile, so there is no second login. The licence and Epic's EU withdrawal waiver are accepted only with `FAB_ACCEPT_EULA` (on by default), the buttons are pressed with the mouse, and an asset you have left alone is not looked at again for three days.
- 🟢 `unity.py` (**New**, opt-in): Claims the weekly free Publisher of the Week asset on the Unity Asset Store. The asset is free only with a coupon that changes every week, so the code is read off the sale page on each run and never cached. In the countries where Unity asks about consumption tax, its checkout starts on "exempt: yes", which silently blocks the coupon; the bot answers No when the account carries no tax number and refuses to confirm any order whose total is not exactly zero. After pay.unity.com it confirms the claim on the orders page, and an owned asset is left alone for three days.
- 🟢 `ubisoft.py` (**New**): Claims Ubisoft giveaways. Detection is a pure function over the JSON feed embedded in `ubisoft.com/games/free`, with no browser involved. Giveaways share their type with ordinary trials, so the filter also demands a real promotion window and the claim page has to identify itself before anything is clicked.
- 🟢 `microsoft.py` (**New**): Redeems the Microsoft Store and Xbox codes Prime Gaming hands out, and claims paid games while they are free to keep. The store's own catalogue decides: a game counts only when its list price is above zero and its price is zero, which keeps free to play titles and Game Pass out, and the purchase window has to show zero again before anything is confirmed.
- 🟢 `prime.py`: Fixed critical DOM selector bugs from the JS version. Amazon recently injected "Sign in with Passkey" prompts which trapped the old script in an infinite loop. The Python port explicitly targets the standard form. It also differentiates between natively claimed Amazon games and external keys (e.g. extracting GOG activation codes), and keeps writing `data/prime-gaming.json` next to the database for anyone who parsed that file in the JS days. The log shows only the start of each code; the whole code goes to your notification and that file. A code that was not on the page yet is looked for again on the next run.
- 🟢 `legacygames.py` (**New**): Redeems the Legacy Games codes Prime Gaming hands out into your Legacy Games account in the same run, since they expire within days. It runs by default and asks for `LG_EMAIL`/`LG_PASSWORD` only once a code is waiting; the newsletter box is unticked before the code is sent, and a code counts as redeemed only when the game shows up under My Free Games.
- 🟢 `gog.py`: Streamlined the giveaway banner parsing logic. It also redeems the GOG keys Prime Gaming hands out.
- 🟢 `steam.py` (**Completely New Feature**): Replacing the useless original script, this entirely new module takes GamerPower's Steam giveaways first and then Steam's own store search, where only the rows Steam marks as 100% off at a price of zero count, so free-to-play games never slip in, then logs into Steam to finalize the 100% discount purchases. A page without the 100% discount is free for good and is skipped before any base game is added. A claim counts only when the store page shows the game in your library afterwards. It also activates the Steam keys Fanatical giveaways hand out, on Steam's own key page, and never logs a key in full. A paid find is left alone for 20 hours before it is looked at again.
- 🟢 `gamerpower.py`: Reads the GamerPower API once per run, when a store in it can use the answer, for giveaways the storefronts themselves do not advertise, then hands each one to the store it belongs to, which claims it in the browser session it had opened anyway. Routing goes through `url_security.py` and is remembered for two weeks in `data/gamerpower_routes.json`, so each link is looked up once (the page it ends at is fetched without signing in); DLC are looked up only when GamerPower gives them a price, and go only to a store that takes them (`STEAM_CLAIM_DLC`, `EG_CLAIM_DLC`, `MS_CLAIM_DLC`; itch.io, IndieGala and Fanatical always), and the sites with no module of their own (Fanatical, Itch.io, IndieGala, Alienware Arena) are chosen in `STORES` like any other store, because each needs an account there. A claim on those sites counts only when the site's own library or orders list it; for Fanatical that is its orders API, which also hands over the giveaway's Steam key, and only that one key is ever revealed. A Fanatical key the claim did not show is read later from Order History & Keys (every 20 hours, five looks). An itch.io giveaway that is a download only is reported once and opened again only every three days. Alienware Arena giveaways are only passed on to you, since they cost ARP points and a captcha.
- 🟢 `ms_rewards.py` (**New**, opt-in): Microsoft Rewards: the daily set, one-visit tasks and punch card steps, Keep earning searches and Bing searches up to the day's limit, streak protection kept on, and points claimed before they expire. Every click and keystroke is a real mouse or key event. With Microsoft's bot warning on the dashboard it only claims what was already earned. It never sets a reward goal and never redeems. It runs only when `STORES` names `msrewards`, and shares the Microsoft Store profile when it is the same account.
- 🟢 `aliexpress.py`: The daily check-in module. It carries one coherent `browserforge` Android fingerprint, reads the coin balance by intercepting the store's own API response rather than the animated DOM, and treats a low-trust reward (1 coin instead of the full amount) as a reason to back off rather than to collect. Check-in state is read from the page in all 18 of its languages, with the labels taken from AliExpress's own translations and a collected day taken from the calendar's own mark, and the check-in API confirms it. The phone names the version of the Chrome actually running, moved along when the image's Chrome updates.

### C. Docker Infrastructure
- 🟢 `Dockerfile`: Debian `trixie-slim`, with `google-chrome-stable` on x86-64 and `chromium` on ARM (Raspberry Pi). The image also carries the fonts Noto Color Emoji, Cantarell, Carlito and Noto CJK. The stack still includes `TurboVNC`, `VirtualGL` and `noVNC` on port 7080 (the original used 6080), now `NOVNC_PORT`, so you can watch the browser or solve a captcha exactly as before. Two Chrome-level details matter for AliExpress: `xdg-open` is neutralised, and a managed Chrome policy pre-answers the "Open xdg-open?" dialog for app schemes, which otherwise froze the session behind a system prompt nobody was there to click.
- 🟢 `docker-entrypoint.sh`: Like the original, it clears the profile lock (`SingletonLock`) a hard stop leaves behind, which would otherwise keep Chromium from starting; `start-vnc.sh` clears the screen's X lock. Its first log line names the user the container runs as and whether the data folder is writable, the two things a NAS template usually changes.
- 🟢 `start-vnc.sh`: Starts the virtual screen and noVNC, both at boot and whenever the bot finds the screen dead. TurboVNC's errors go to `data/TurboVNC.log` and noVNC's (websockify) to `/tmp/websockify.log`, instead of `/dev/null`. It warns at start when `VNC_PASSWORD` is empty.
- 🟢 Running as your own user: with `PUID`/`PGID` set, the entrypoint starts as root only long enough to create that user and hand it the data folder, then runs the screen, noVNC and the bot under it through `setpriv`, so the browser that visits outside sites does not run as root. Without them the container runs as root, as before.

### D. Tests (`tests/`)
The original had no automated test suite, only five manual scripts. This one covers what can be checked without a real browser, an account or a network: payload parsing, offer filtering, hostname checks, store selection, the notification summary filter, `.env` parsing, the log mask, and whether the documentation still matches the code. Store flows such as Epic's page opening and the Fab and Fanatical checkouts run against stand-ins for the browser, so a change that would order a paid item or skip a security check fails a test. It runs in a few seconds with `python -m pytest tests/ -q`, GitHub runs it on every change to the code, and it exists because several regressions in exactly these areas shipped before it did. Real pages are still verified by launching a real browser and reading back what it produced.

## 4. Verification Check
If you wish to verify the integrity of the project:
1. Examine `requirements.txt`, you will find standard, widely used open-source libraries (`nodriver`, `sqlalchemy`, `aiosqlite`, `httpx`, `apprise`, `apscheduler`, `psutil`, `browserforge`, `pyotp`, `tenacity`, `rich`, `python-dotenv`, `tzdata`, and `pytest` for the tests).
2. Search the bot's code (`main.py`, `src/`) for execution tools (`os.system`, `eval`, `exec`), you will find them absent. The tests evaluate expressions from the project's own source and run `.github/scripts` under bash. There are three uses of `subprocess`, two of them in `src/core/claimer.py`. `chrome_version()` runs the installed Chrome with `--version` before AliExpress starts, so its phone can name that same version. When Chrome refuses to start, the bot runs that binary twice more, once with `--version` and once headless on `about:blank`, and puts what it printed into the log, because otherwise a failed start says nothing at all. In `src/core/display.py`, when the virtual screen has died, it runs the project's own `start-vnc.sh` to start it again. Nothing else is executed, process cleanup goes through `psutil`, and the only thing evaluated is JavaScript sent to the browser you can watch over noVNC.
3. Review outbound requests (search for `httpx.AsyncClient` and `page.get`), you will see the target stores, `gamerpower.com`, `api.github.com` for the release check, `ipapi.co` and `ipwho.is` for the time zone, and exactly the webhook domain you provide in your `.env`. One more request never leaves the machine: when Chrome is slow to start, `wait_for_chrome()` in `src/core/claimer.py` asks Chrome's own control port on the loopback address (127.0.0.1) whether it is ready, and that request ignores proxy settings.
4. Run `python -m pytest tests/ -q`. It touches no accounts and no network, so it is safe to run before you trust the thing with your credentials.
